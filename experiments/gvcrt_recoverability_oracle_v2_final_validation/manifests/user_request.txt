# 一、核心目标

对上一轮 Oracle 实验进行最后一次严格验证，回答以下问题：

在固定 GVC-RT 编解码器和相同真实传输码率的条件下，基于局部干预收益进行量化分配，是否能够稳定改善最终重建视频的感知质量？

本次实验不是新模型训练，不修改 P 模块，不训练 Bridge，不修改 GVC-RT 权重，不进行无关的 loss 搜索。

本次只修复和验证：

1. 候选方案选择逻辑。
2. 实际码率预算与匹配。
3. Oracle、随机策略和启发式策略之间的公平对照。
4. 局部收益的可重复性及联合干预验证。

# 三、修复候选选择逻辑

- 重复候选、无效候选和码率收益估计错误。

# 四、首先确认是否存在有效的真实码率控制接口

上一轮实验已经证明，局部量化步长干预可以运行，但并未建立公平的同码率策略比较。

请先检查当前实际熵编码器和码率控制接口，优先寻找以下方案：

1. 使用原生 QP 或量化尺度控制，在局部干预后调整整体量化设置，使最终实际码率接近目标。
2. 如果可以合法调整局部量化步长，则使用联合候选选择与预算约束优化。
3. 如有必要，探索多个局部干预组合与少量全局 QP 候选的联合搜索。
4. 所有方法都必须通过真正的编码器产生合法码流，并由真实解码器解码。

注意：

- 不得直接修改已经生成的 bitstream 来假装实现新的码率分配。
- 不得只在解码端修改潜变量而不在编码端同步实现。
- 不得将不同 QP 下的基线简单当作同码率对照。
- 不得将不等码率的质量比较宣称为公平的率失真改进。
- 任何改变参考帧内容的干预，都必须在实际因果编码/解码链上处理后续帧。

## 码率匹配标准

优先追求实际总码率完全一致。

若系统的离散量化机制无法做到完全一致，可在实验开始前明确一个可执行的近似匹配容差，并记录其依据。只有当对照之间的实际码率差异满足预先设定的容差，且不会改变结论时，才允许纳入近似同码率比较。

所有策略必须将以下开销纳入总码率：

- 主码流。
- 必要的局部量化控制信息。
- 必要的侧信息。
- 其他实际传输的控制字段。

如果局部控制信令开销使策略无法满足码率预算，应如实记录，不能忽略。

# 五、实验规模与分支

采用小规模、可复现的设计，不进行全数据集长时间扫描。

优先从上一轮有效基线中选择：

- UVG holdout
- HEVC-B
- MCL-JCV
- U-Long

优先选取每个数据集 1–2 个代表性视频片段，以及两个实际可运行的码率工作点。

如果某个数据集或码率配置缺乏有效基线，跳过该配置并记录原因，不得伪造或自行推测基线数据。

比较以下策略：

A. `A_native_baseline`

原始 GVC-RT 编码策略。

B. `B_random`

在合法候选集合中随机选择局部量化干预。固定并保存多个随机种子，不能只挑选表现最好的随机结果。

C. `C_temporal_or_content_heuristic`

如果已有合法的运动或内容重要性特征，使用固定规则进行候选选择。没有可靠特征时明确跳过，不需要为了凑齐分支而开发新的重要性网络。

D. `D_oracle`

基于离线测得的局部真实干预收益，在相同码率预算下寻找候选方案。

Oracle 必须在明确的候选集合内进行预算约束优化。可以使用穷举、动态规划、整数规划或有明确约束的贪心算法，但必须记录所用方法，并明确其是否为全局最优。

不得将局部贪心算法的结果称为数学意义上的全局上界。

# 六、Oracle 选择与验证协议

为避免 Oracle 只在单个视频上过拟合，按以下方式执行：

1. 使用少量预先指定的校准片段估计候选干预收益。
2. 对这些片段建立局部干预收益表和真实码率表。
3. 在校准片段上确定 Oracle 选择策略。
4. 在同一数据集的独立视频片段上测试固定的选择策略。
5. 如果样本不足以进行独立划分，明确标记为探索性验证，不声称跨视频泛化。
6. 随机策略必须执行相同的候选约束与码率匹配规则。
7. 任何候选方案在真实编码后未达到码率约束时，记录为无效候选，不得通过修改结果表将其视为成功。
8. 对实际选择出的联合干预方案重新编码、解码并评价，不能仅把各个单块的收益简单相加作为最终结果。

如果没有有效的局部码率控制方式，允许将结果限制在“局部敏感性验证”，但必须停止声称已经完成 Oracle 同码率比较。

# 八、预先定义停止条件

本次实验的目的是决定研究方向，不是无限优化 Oracle。

满足以下任意一项时，停止扩大实验规模，并保存已有产物：

1. 经过合理修复后，依然无法实现合法、有效的真实局部码率控制。
2. 在当前模型支持的候选集合内，无法形成有效的码率匹配方案。
3. Oracle 仅在校准片段有效，而在独立测试片段上没有稳定收益。
4. 在公平同码率比较中，Oracle 没有表现出具有实际意义的质量改善。
5. 实验成本明显超出小规模可行性验证的范围。

停止后应保存失败记录、现有数据及阻塞原因，不允许通过放宽评价标准或忽略控制开销来强行完成任务。
