# GVC-RT Latent Enhancement V1 — 实测报告

日期：2026-09-14。运行：`run_v1`。**整体结论：PARTIAL-GO；接口结论：INTERFACE-PASS。不满足 GO。**

## 1. 核心结论

本轮完成了阶段 A–D 的有界真实执行：Train2 连续诊断 500 步、量化训练 1000 步、固定 Train8 泛化训练 1500 步；增强模型和无码流对照各累计 3000 次更新。固定 Val6 全部完成四个原版 QP 点及三个真实增强码率点的评价，没有扩大数据集或追加调参。

**当前接口可以通过学习 latent 修正提高 RGB PSNR，但没有证据证明“新增源侧传输信息”有效。**

- 最低增强码率点在 Val6 上达到 **26.4504 dB**，比同精度基础参考 **23.7170 dB** 高 **2.7334 dB**。
- 同时，无码流、只读基础 ell 的修正网络已经达到 **26.3810 dB**。增强版本只高 **0.0694 dB**，逐视频 4 胜 2 负。
- 更关键的是，最低码率 delta=2 点在 Val6 的 **90 个 P 帧、367,200 个增强符号中全部为零**。其额外 **65.148 kbps** 没有携带新的源侧内容。这里仍然实际发送、解码并计费，绝不把全零符号当作无增强旁路。
- 更细的量化发送了非零符号，却花费更多比特并获得略低的平均 PSNR。因此目前的主要收益应解释为新增修正网络/优化目标的作用，不能解释为新增信息的作用。
- 感知质量并未同步提高：Val6 LPIPS 从同精度参考 **0.23593** 恶化到 **0.30598**（约 +29.7%，越低越好）。画面出现纹理平滑，不能只用 PSNR 宣称整体保真度或感知 RD 全面改善。

本结论针对本轮固定架构、训练预算和短片段，不推断整个 latent enhancement 方向不可行，也不宣称创新成立。

## 3. 阶段 A：真实路径、旁路与梯度

本地 P 路径为：实际基础编码/量化/熵编码 → y_hat → 基础特征解码 → feature_base → Latent Adapter → ell_base/codeword → De-tokenizer G → RGB。

| 张量 | 实测 NCHW |
|---|---|
| 基础压缩 y_hat | 1×128×68×120 |
| feature_base | 1×256×136×240 |
| ell_base/codeword | 1×18×68×120 |
| q_recon | 1×320×1×1 |
| 原版重建 | 1×3×1088×1920 |

不在不同 latent/feature 空间相减。插入点就是 `PretrainedReconWrapper.forward()` 中生成 codeword 之后、`self.decoder(codeword, quant_step)` 之前的等价显示分支。详细代码定位和数值范围见 `audit_notes.md`。

- **无增强精确复现：通过。** 同路径输出 `torch.equal=True`，ell 未改动，后续 DPB 完全一致；额外运行了无增强文件、完全不构造 E/D 的独立接收 CLI，8 帧均与基础缓存精确相同。
- **因果参考：通过。** 不同 checkpoint 实例独立基础解码重放精确相同；12 帧专用审计覆盖 I/P 切换和 feature reset，参考 hash 一致。增强 RGB 从不写入基础 DPB。
- **发送端与接收端 ell：通过。** 来自真实基础文件解码；端到端检查另行确认 ell、q_recon、基础 RGB 精确一致。
- **梯度：通过。** 首步编码器梯度为零符合零输出头初始化；第二、三步编码器 L2 梯度约 2.60e−4、4.97e−4，解码器梯度非零。原版参数无梯度，完整 DMC 权重 hash 不变；正式 B/C/D 冻结 G 的 hash 检查也全部通过。
- **执行路径：** 环境没有融合 CUDA 扩展，官方入口实际走 PyTorch fallback。独立同 FP16 路径与官方 fallback 精确一致。FP32 G 对相同 FP16 ell/q 的 RGB 最大差异 0.0106207、MSE 1.5031e−7；这些差异没有计入增强收益。没有宣称验证了不可用的融合 CUDA 路径。
- **增强真实编码：通过。** 独立算术编码、边界符号、溢出拒绝和实际文件 round-trip 成功。首次使用原生 rANS 的小型高熵边界测试挂起，发现其 N 字节缓冲不足以安全支持任意 N 符号；中断文件保留在 `stage_a`，修复证据在 `stage_a_v2`。

接收程序安装源访问阻断 hook，禁止访问源视频、源 PNG、发送端基础 `.pt` 缓存。24 个独立接收进程均通过整数 hash 和重建逐像素一致性检查。

实际比特包含 GEC1 序列头、逐帧长度、GLE1 网格/delta/CDF 指纹头、算术编码终止和字节对齐。基础流包含原 SPS/NAL。最低档实际增强比估计高约 **13.63%**；它仍比基础层额外增加 **45.75%** 比特，不能把它描述为几乎免费的增强。

### 量化差距

以同一个阶段 D checkpoint 的连续读出作为对照，“连续 PSNR − 量化 PSNR”在 delta=0.125/0.5/2 下分别为 **−0.00325 / −0.02197 / −0.03029 dB**。本轮没有明显的正向量化损失；粗量化略好更符合源侧分支利用不足/轻微正则化的表现，而不是渐进质量提升。这里比较的是同一量化训练模型的连续/量化读出，不把阶段 B 与 D 的训练变化当作量化误差。

### 新增源信息是否有作用

`run_v1/symbol_utilization.json` 从真实文件解码统计：

- delta=0.125 与 0.5 均有非零、随源片段变化的符号，但并未优于全零的最低档。
- delta=2：Val6 每个视频均为 15 个全零增强网格，每段真实 `.gle` 仍为 4488 字节。这些符号没有传递新源内容；GEC1 中基础流 hash 也只是双方已知基础流的标识。
- 最低档相对 base-only 的逐视频 PSNR 差为 **+0.0778, −0.0237, −0.1149, +0.1126, +0.2999, +0.0647 dB**，平均 +0.0694 dB。由于这一点根本没有源内容符号，差异应归入网络结构/初始化/优化路径差别，不能归为传输信息收益。
- base-only 解码网络 30,418 参数，增强 D 为 35,026 参数，训练数据、步数及图像目标匹配，但不是完全相同的初始化/参数化。只跑了一次固定种子训练，未估计微小差异的重复训练方差。

### 同总码率比较

使用**每个视频**四个原版真实采样点，按 PSNR 对 log(bpp) 做分段线性插值，只在实际重叠区间内计算，不外推：

- delta=2 六个验证视频均位于各自原版采样码率区间内，相对插值原版的 PSNR 差为 **+2.7028, +1.9281, +2.3220, +2.8708, +1.1445, +1.2550 dB**，平均 **+2.0372 dB**。
- delta=0.5 仅 1/6 视频与本轮原版点重叠，该视频为 +2.2997 dB；其余不能作同码率结论。
- delta=0.125 全部超出本轮原版采样上界，未作同码率提升声明。

这说明当前 **PSNR** 数值可以优于原版采样曲线，**并不证明需要新增信息**：无码流修正几乎实现了全部质量收益，且 LPIPS 明显更差。没有宣称 MS-SSIM/LPIPS 同码率优势、没有计算极小样本 FID，也没有把不重叠码率点硬写成同码率。

## 6. 时间稳定性和可视化

保存了源视频、原版、连续增强、base-only 和实际解码增强的逐一对应 **FFV1 无损 review 视频**。可查看 `run_v1/review/` 的 Train2 配对图，以及 `run_v1/review_val6/` 的六个 Val6 配对图（帧 0/I、1/P、8/P、15/P）。

实际检查六组图像：增强后的田地、茶园、水面、头发/羽毛等纹理更平滑，与 LPIPS 恶化一致；原版 I 帧保留锐利纹理，增强 P 帧的平滑风格可造成 **I→P 锐度/纹理观感变化**。不把它称作已经解决时间稳定性。检查的 P 帧时间点未见明显新增的全局颜色突变；仅靠这些短片和静态时序抽样，不能排除局部闪烁或长序列不稳定。

浮点有效区域的未配准“相邻重建误差差分 MSE”从基础参考 **0.00283064** 降到 delta=2 的 **0.00227818**（约 −19.5%），六个视频均下降；8bit review 的 I→P 和 P→P 分开统计也均低于原版。它会受平滑影响，**不是专门的闪烁检测器**，不能用该下降证明感知时间一致性改善。详细数值在 `review_val6/transition_diagnostics.json`。

## 8. 七个问题的直接回答

1. **零增强是否精确复现原版？** 是，真实文件、同执行路径、独立接收端及后续参考状态检查均通过。
2. **连续增强能否纠正原版生成误差？** 能优化像素误差；Train2 +1.9247 dB、Val6 连续读出约 +2.7031 dB。但 LPIPS 变差，主要表现包括平滑，不能等同于细节被真实恢复。
3. **量化损失多大？** 同 checkpoint 连续与真实量化质量差很小，Val6 粗量化反而约高 0.0303 dB；当前主要瓶颈不是大的量化失真。
4. **新增传输信息是否优于 base-only？** 未证明。最好档位全零，无新源内容；微小网络差异不能计为信息收益。
5. **相同总码率是否优于原版？** 最低档在全部六个视频的实际重叠区间内，相对 log(bpp) 插值原版有平均 +2.0372 dB 的 PSNR 优势；它几乎由无需码流的修正作用解释，且感知指标变差，因此不是整体 RD/新增信息成功。
6. **是否有新的时间不稳定？** 看到了 I/P 纹理锐度风格变化；未在检查的 P 帧抽样中观察到明显新全局颜色突变。时间误差诊断下降，但短片/静态检查不足以排除闪烁或证明长期稳定。
7. **新增参数、显存、时间？** 163,042 参数；训练峰值约 9.021 GiB；完整参考端到端实测 536.552 ms/帧、峰值约 1.412 GiB，计时包含发送端获取基础 ell。

## 9. 结论边界与产物

**PARTIAL-GO** 的含义：接口、梯度和真实传输链路可行，PSNR 优化有收益；但当前增强信息利用不足、感知质量退化，且没有可归因于新增源信息的稳定额外收益，因此 **不升级为 GO**。单个 seed、8 个训练视频、6 个验证短片（每段约半秒）、未知父视频对应关系以及缺少融合 CUDA 扩展均限制结论。训练预算按配置完成，未把训练不足直接解释为方向无效。
