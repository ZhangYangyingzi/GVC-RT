# GVC-RT 低码率实验与后续研究计划

## 一、研究目标与实验设置

我们关注极低码率下的视频重建质量，以及 GVC-RT 在可传输信息减少时是否出现明显的性能退化区间。本实验的“我们的方法”指 GVC-RT 的 `C_C1_lr2_FD_1000` 检查点；对照为 GVC-RT 原始权重。该检查点从 v6.22 的 B1 第 1000 步初始化，继续训练 1000 步；冻结预处理 wrapper 和压缩骨干，仅更新 bridge 和生成器，使用包括 FD 的固定损失配置。不能将其描述为从头训练的新编码器。

所有方法使用同一批 66 条测试视频，每条视频取原视频前 64 个连续帧，直接中心裁剪到 854×480，不缩放，按 30 fps 编码；码率使用完整实际码流字节数 × 8 / 64 × 20 / 1000，单位 kbps。**图上是 20 fps 折算码率，不是该 30 fps 序列的实际每秒码率；同一码流按 30 fps 报告时数值乘 1.5。** 对 UVG 等非 30 fps 原片，取的是原始连续帧并按 30 fps 编码，未先重采样到 30 fps。结果因此不等同于原论文的标准全分辨率、全时长测试。

指标：RGB PSNR 越高越好；LPIPS（AlexNet）、DISTS 越低越好；FID 越低越好，使用 Inception 2048 维特征，对数据集内所有视频的 64 帧池化计算。PSNR、LPIPS、DISTS 先逐帧再逐视频平均。FID 不是逐帧指标，相邻帧相关、UVG 只有 3 条，需谨慎解释。

### 对比方法

- GVC-RT original 与 `C_C1_lr2_FD_1000`；额外低码率点采用实验性编码端/解码端共同设置的高斯熵模型置零阈值，外部 QP 固定为 0，阈值从 0.12 扩展到 8，19 个配置；编码产生真实码流并由独立实例检查每帧状态。
- 传统编码 H.264/libx264、H.265/libx265、H.266/VVenC；H.266 已增加 QP 54、57、60、63，补足低码率。VVenC 使用低延迟 B-slice、无未来参考；H.264/H.265 使用 P 帧，因此预测结构并不完全相同。
- DCVC-RT 与 GLC-Video。GLC 使用仓库内自定义、非官方的 rANS 真实码流实现，其质量档位由原模型支持的配置决定。GLC 在 HEVC-B、MCL-JCV、UVG、U-long 的最低数据集平均码率分别为 83.63、93.55、66.50、69.49 kbps，超过图中 50 kbps 上限；Kitware 最低约 35.15 kbps。没有 0–50 kbps 点不意味着 GLC 在该区间表现差。
- S²VC 尚未运行，PLVC 未纳入本次比较；不能将论文数据当作本实验实测结果。

### 训练数据和隔离

本次 C 分支的训练计划共 1000 次更新，500 次采样 U-long、500 次采样 UVG。U-long 候选池 1020 条；UVG 训练源为 Beauty、ReadySteadyGo、ShakeNDry、YachtRide，测试源为另外三条。训练计划实际使用 415 个不同源文件。已有审计在本轮原有 46 条测试源上，训练/测试路径和 SHA256 交集均为 0；该审计不包含此次额外抽取的 20 条 Kitware 视频，也未做穷尽的感知近重复搜索，不能排除原始预训练权重的历史数据暴露。U-long 来源及外部认可度需进一步核实。

## 二、结果与低码率“拐点”

### 当前结果

低码率扩展共 66 视频 × 2 权重 × 19 阈值 = 2508 个点，独立解码状态校验通过。以下均为**数据集平均**，不是同一码率等率比较：

| 数据集 | 方案 | 原始阈值 0.12：码率 / PSNR / LPIPS / DISTS / FID | 阈值 0.32：码率 / PSNR / LPIPS / DISTS / FID |
|---|---|---|---|
| HEVC-B | 我们 | 28.13 / 22.76 / 0.243 / 0.144 / 79.59 | 13.04 / 21.35 / 0.374 / 0.206 / 165.16 |
| MCL-JCV | 我们 | 34.82 / 24.40 / 0.203 / 0.149 / 63.65 | 18.20 / 22.76 / 0.322 / 0.217 / 142.22 |
| UVG 3 条 | 我们 | 22.37 / 25.06 / 0.174 / 0.129 / 37.43 | 10.52 / 23.06 / 0.263 / 0.182 / 123.88 |
| U-long | 我们 | 24.61 / 24.83 / 0.175 / 0.122 / 67.57 | 12.94 / 23.20 / 0.307 / 0.214 / 201.15 |
| Kitware | 我们 | 13.41 / 23.15 / 0.179 / 0.122 / 82.00 | 6.63 / 21.64 / 0.259 / 0.155 / 150.25 |

在原始阈值 0.12 的 QP 0 设置下，例如 UVG 三条视频上，我们的 LPIPS 为 0.174、FID 为 37.43，original 分别为 0.193、60.74；但我们平均码率 22.37 kbps、original 21.90 kbps，且我们的 PSNR 25.06 dB 低于 original 的 25.39 dB。这是同一外部 QP 的描述，不是严格等率性能增益。不能据此笼统称我们在所有指标或所有数据集上领先。不同方法仅在真实测得的共同码率范围内做插值比较，不外推。

### 可报告的候选退化区间

可以观察到一种值得研究的现象：继续提高置零阈值后，部分数据集的平均码率变化很小，质量仍明显恶化。例如 HEVC-B 上阈值从 0.32 到 0.40，我们的平均码率从 13.04 降到 12.00 kbps（约下降 8%），PSNR 从 21.35 降到 20.45 dB，LPIPS 从 0.374 升到 0.438，DISTS 从 0.206 升到 0.263，FID 从 165.16 升到 232.26。U-long 上从 0.32 到 0.40，码率由 12.94 降到 12.31 kbps，PSNR 由 23.20 降到 22.37 dB，LPIPS 由 0.307 升到 0.356。可以将 HEVC-B 约 12–13 kbps、U-long 约 12–13 kbps 称为**本次实验设置下的候选陡降区间**，不宜称作唯一精确拐点。

UVG 和 Kitware 的码率对阈值不严格单调，部分点质量继续变差而平均码率略升；高阈值趋于平台。因此把按码率排序的点连成单值曲线可能掩盖配置差异。不同视频/指标的临界区间不同，尚未做主观评价、逐视频变点拟合及统计置信区间。目前只能说观察到候选退化/平台现象，不能证明普适“信息熵下限”，也不能宣称低于某个固定码率必然崩塌。高阈值是额外编解码配置，需将阈值作为双方已知侧信息或纳入码流；当前结果未计阈值信令开销。

## 三、后续工作：解码端已知信息与低码率恢复

受到 [S²VC（CVPR 2026）](https://openaccess.thecvf.com/content/CVPR2026/html/Xue_Single-step_Diffusion-based_Video_Coding_with_Semantic-Temporal_Guidance_CVPR_2026_paper.html) 启发：它从缓存特征提取上下文语义，并采用时间一致性引导，以改善单步扩散重建。我们的设想不是断言现有 GVC-RT 完全没有利用上下文——它已经具有参考帧/特征与时序熵先验——而是系统检验这些**解码端已经可获得的信息**是否还有未被充分利用的条件信息。

1. 在不引入未来帧或原始帧泄漏的前提下，分析当前解码潜变量、已解码参考帧、DPB 缓存特征、运动和结构提示，与当前生成器输出误差之间的关系；做可用性与消融实验。
2. 使用这些双方可获得的上下文作为生成器或条件熵模型的输入，构建轻量的语义/时序条件模块；验证无额外码率和显式侧信息两种情形，并计入所有信令与模型条件成本。不能将生成先验补出的细节视为确定恢复了原视频信息。
3. 在相同实际码率下对照原始权重、现有方法和新方案，考察 PSNR、LPIPS、DISTS、FID、主观重建视频及时间一致性；记录模型体积、显存、编解码耗时。先用单视频和严格独立解码做可行性检查，再扩展至完整数据集。
4. 用逐视频分段拟合、视频级重采样置信区间和预先定义的可接受画质标准，辨别低码率退化区间；增加接近候选区间的实际码率点，避免对非单调实验配置强行宣称单一拐点。
