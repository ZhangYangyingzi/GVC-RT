# GVC-RT recoverability oracle feasibility

Fixed original GVC-RT weights. No training, P module or weight updates. Four inherited evaluation identities;16 native-resolution frames;QP2/7. Audit and executable configuration are under audit/ and configs/.

Run: `/Huang_group/zyyz/home_dir/.conda/envs/gvc-rt/bin/python -B src/driver.py` from this directory (GPU4/5/6/7 only). Individual commands and stdout/stderr are saved under logs/ and manifests/. Completed atomic receipts are resumable.

Baseline: baseline/. Local interventions: oracle/local_sensitivity/. Allocation trials: oracle/rate_allocation/. Raw tensors, complete streams and lossless sample reconstructions: artifacts/ (not Git; indexed with server paths and SHA256). Metrics are computed from floating-point native reconstructions before video export. FID is not computed for these small pools. Experimental block control must pass decoder/causality correctness before allocation is enabled. Exact actual-rate matches are labelled separately from unmatched trials. See run_status.json for status; no population or optimality conclusions are made.


The source-video selection is fixed in `manifests/videos.json`: one inherited 16-frame clip from each of UVG (HoneyBee), HEVC-B, MCL-JCV and U-Long, at external QP 2 and 7. The native 1920x1080 inputs are padded to 1920x1088; rate accounting uses 30 fps. Actual frame QPs include the inherited P-frame shifts and are recorded individually. The codec's deterministic setup resets the effective Torch seed to 0; the configured seed 20261018 also controls offline random allocation choices.

All strategy A budgets use `artifacts/runs/<baseline>/native.bin`, without the experimental envelope. Modified runs include 10 fixed control bytes and 11 bytes per decision. The original envelope-wrapped baselines remain available as raw records; their native-stream rates are reported separately. An exact byte match is required for a fair equal-rate comparison. Adjacent legal global QPs are tried for calibration; unresolved deviations are retained as unmatched results.

The correctness pilot includes a factor-1 control and factors 0.5/2 at one latent-grid rectangle. In addition to paired and fresh-model decoder checks, each pilot runs `src/decode_stream.py` in a separate interpreter using only the persisted stream and fixed model weights. Expansion requires successful pilot worker receipts. The full bounded plan has 64 single interventions (4 blocks x 2 levels x 8 video/QP points), 8 joint validations, 24 allocation trials, and up to 48 global-QP calibration trials. The oracle exhaustively searches 81 additive surrogate states; actual joint streams are re-encoded and measured. No claim of global optimality for the actual interacting codec is made.

Resume safely with `/Huang_group/zyyz/home_dir/.conda/envs/gvc-rt/bin/python -B src/launch.py` after confirming the previous launcher has exited; a file lock prevents two launchers. Already successful immutable jobs are skipped. `manifests/driver_process.json`, `logs/driver_exit.json`, per-job receipts, `logs/stage_exits/` and `logs/standalone_exits/` preserve process status. GPU resources are logged to `logs/GPU_resources.jsonl`. The scheduler uses only GPUs 4–7, one experiment worker per GPU, with at least 7000 MiB free at launch. Independent failures do not cancel other jobs. A resource wait lasting 1800 seconds with no active experiment worker is recorded as a failure rather than left indefinitely pending.

Read-only copies of consumed historical helper sources are under `src/dependency_snapshot/`; their original paths and SHA256 values are in `manifests/dependency_sources.json`. Runtime continues to use the audited server paths. `manifests/environment.json` and `manifests/metric_weights.json` record the environment and metric weight hashes. Dataset and model files remain on the server and are not committed. Raw binary outputs are indexed with server paths, byte counts and SHA256 at completion. `manifests/artifact_validation.json` independently verifies saved bytes, tensors and temporal aggregation. `metrics/per_transition/` preserves raw FloLPIPS transition scores.

Publishing uses `src/publish.py` in an isolated latest-main worktree and changes only this experiment directory. A running checkpoint is explicitly labelled as such. After the GPU plan finishes, the driver runs final validation, saves CSV/JSON and exit summaries, and pushes the completed or explicitly partial results. `publication_status.json` records the verified push and commit. A publication failure is saved under `logs/publication_failure.json`; it does not erase the experiment results.
