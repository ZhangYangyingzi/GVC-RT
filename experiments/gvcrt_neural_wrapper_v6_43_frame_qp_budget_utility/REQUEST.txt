一、目的与固定范围

回答以下可测量的问题：
1. 改变某一帧的实际 QP，会怎样改变该帧的质量、后续质量以及各帧真实字节数？
2. 按当前帧收益排序，与按当前及后续收益排序，结果是否不同？
3. 按测得的收益选择两个位置转移预算，在不超过基线总字节数时，能否改善整段视频？

仅做离线诊断。允许用 GT 计算收益和选择候选，但必须标注这是使用真实参考视频的 oracle 实验，不能当作可部署的码率分配算法或泛化结果。

不训练、不新增预测器、不调整任何模型权重。

三、先复现基线

每个视频以 external QP=5 的历史逐帧 QP 序列为基线。
直接读取 v6.42/stream_manifest.json 中对应的 actual_qps，不能把所有帧都设成 5。

重新编码并独立解码两条完整基线码流，检查：
- 完整码流字节数、SHA256 与 v6.42 对应历史码流一致；
- G_basic 解码输出哈希及指标与 v6.42 对应结果一致；
- 逐帧实际 QP、I/P 布局、参考状态和码率口径一致。

基线不能复现时，先修复实现差异，不进入正式干预；不得把不一致的结果直接当作新基线。

四、单帧 QP 干预：固定 24 个变体

零起始目标帧固定：
T = [8, 16, 24, 32, 40, 48]

这些位置处于相同的历史 QP 周期相位，并且都有完整的后续 15 帧。

每个视频、每个 t，分别运行：
- qplus2：仅该帧 actual_qp = baseline_actual_qp[t] + 2
- qminus2：仅该帧 actual_qp = baseline_actual_qp[t] - 2

其余所有帧的 actual_qp 保持基线值。
这是直接修改一个帧的最终 actual_qp，不能再重复应用 shift_qp，也不能修改整个视频的 external QP。

检查 QP 索引合法，不允许静默 clamp。
用真实编码字节判断哪个操作增加或减少预算，不能仅根据“QP 越大/越小”的传统约定命名质量档位。保留 qplus2/qminus2 原始标签。

重要实现要求：
- 每个变体都从同一个原生 I 帧状态开始编码。
- 干预 t 后，t+1–63 必须使用该变体演化出的参考状态重新编码。
- 禁止把变体的第 t 帧码流直接拼接到基线后续码流上。
- 禁止在 t 后恢复基线参考状态。
- 每个变体保存完整真实 RANS 码流，并用独立解码器从 I0 解码全部 64 帧。
- 解码器必须从实际码流中的既有 QP 字段获得 QP，不能依赖外部 JSON 才能解码。
- 保存编码端与独立解码端的参考特征检查，沿用项目既有状态同步验证方法。
- t 之前的逐帧码流、重建和参考状态必须与基线一致；t 后允许自然变化。
- QP 同时影响编码特征和生成器条件。本实验测量“逐帧 QP 调整的整体效果”，不能表述成仅改变某一种 latent 的纯因果效应。

先完成 ParkScene 的基线及 t=8 的两个变体作为实现检查，通过后运行剩余任务。这些点计入正式实验，不额外增加试验条件。

五、记录当前收益、后续收益和实际成本

每条码流记录：
- 各帧 actual_qp、帧类型、完整包字节数、payload/header 字节数；
- LPIPS、DISTS、L1、RGB SSE、PSNR；
- 63 个相邻转换的 FloLPIPS；
- 解码参考 feature、Bridge 输出、Generator 输入及条件张量哈希；
- 完整码流大小、SHA256、bpp、实际消费字节数。

各帧字节数按统一规则包含其相关头信息；逐帧之和必须等于完整文件大小。

对每个单帧变体，保存逐帧差值曲线，并使用以下固定定义。
令 b_i 为实际比特数，d_i 为某个越低越好的失真指标：

Δb_i = b_i(变体) − b_i(基线)
g_i = d_i(基线) − d_i(变体)

g_i > 0 表示改善。

所有目标帧采用相同的 15 帧后续观察窗口：
- 当前收益：G_now = g_t
- 后续收益：G_future15 = sum(g_i, i=t+1…t+15)
- 总收益：G_16 = G_now + G_future15
- 当前成本：ΔB_now = Δb_t
- 后续成本：ΔB_future15 = sum(Δb_i, i=t+1…t+15)
- 窗口总成本：ΔB_16 = ΔB_now + ΔB_future15

此外单独记录：
- t…63 的总质量差值和总字节变化；
- 完整 64 帧平均指标与总 bpp；
- 累计到 t、t+4、t+8、t+15 的收益和成本。

整段 PSNR 必须由整体 RGB SSE 换算，不能平均逐帧 dB 代替。
FloLPIPS 单独按转换报告，明确转换两端；不能混入逐帧 LPIPS 的收益和。

六、收益排序：主指标预先固定为 LPIPS

对增加预算且 ΔB_16 > 0 的单帧操作，定义：
U_now = 1000 * G_now / ΔB_16
U_16 = 1000 * G_16 / ΔB_16

单位为“累计 LPIPS 减少量 / kbit”。
两种排序使用同一个成本分母，避免把分母变化误当作当前/后续价值差异。
可附加 G_now/ΔB_now，但必须另列，不能混为主排序。

每个视频独立输出：
- 各目标帧的 U_now 与 U_16；
- 当前排序、含后续排序；
- 前两名是否相同、成对排序反转；
- 有效样本足够且不存在全相同值时，报告描述性的 Spearman 排名相关。

DISTS、L1 用相同方式作为补充表，不重新选择主指标。

若 ΔB_16 <= 0，不计算上述正成本效率，保留收益与成本的原始值并标注类型；不取绝对值、不加任意 epsilon 伪造可排名结果。
额外字节减少且质量改善的情况单独保留。
允许负收益，不删除异常方向结果。

七、小规模预算转移：最多再做 16 个变体

先完成全部单帧实验，再按固定规则为每个视频选择一对位置。

对 qplus2 中满足 ΔB_now>0、ΔB_16>0 的位置，定义增加预算的收益：
A(t) = G_16(qplus2,t) / ΔB_16(qplus2,t)

对 qminus2 中满足 ΔB_now<0、ΔB_16<0 的位置，定义节省预算的代价：
C(t) = -G_16(qminus2,t) / (-ΔB_16(qminus2,t))

只在符合实际成本符号的候选中选择：
接收位置 r、让出位置 d，要求 |r-d| >= 16；
最大化 A(r) − C(d)，并列时按 (r,d) 字典序选取。

即使最大差值为负，也如实记录并按规则执行，不能为了得到正结果改规则。
若不存在符号合法的位置对，记录“无合法预算转移候选”，此阶段按协议不执行，不扩展搜索。

对选定位置对，固定运行两类方案：

正向：
actual_qp[r] += a
actual_qp[d] -= b

反向对照：
actual_qp[r] -= a
actual_qp[d] += b

其中 (a,b) 遍历 [(1,1),(1,2),(2,1),(2,2)]。
每个视频最多 8 个完整编码/独立解码变体。
同样重新编码所有受影响后续帧，不能将两个单帧实验的结果相加当作真实双帧结果。

每个视频以其 q5 基线的完整总比特数 B0 为预算：
- 严格预算可行：B_candidate <= B0。
- 接近相同预算：0.99*B0 <= B_candidate <= B0。

正向、反向各自报告全部四个候选。
在各自“接近相同预算”的候选中，按完整 64 帧平均 LPIPS 最低选一个展示；并列时优先更少字节，再按 (a,b) 排序。
没有符合条件的候选就写“本次有限候选未匹配预算”，不继续扩大网格。

低于 0.99*B0 的候选仍保留数据，注明实际节省比例，但不能称作精确等码率对照。
超预算候选不能用于宣称固定预算收益。
禁止通过填充无用字节、截断码流或仅保持两个 QP 偏移和为零来伪造等预算。
不把使用同一视频 GT 挑选的最好结果当成可部署算法效果。
